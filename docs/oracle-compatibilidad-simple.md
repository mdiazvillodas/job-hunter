# Compatibilidad futura con Oracle Cloud Always Free

Diagnóstico del 18/10/2026. No se creó ningún recurso, no se desplegó y no se modificó el código para Linux.

**Conclusión:** el núcleo Node.js y la persistencia en archivos son trasladables. LinkedIn con Chromium es un candidato viable para una prueba futura; el conjunto completo, especialmente InfoJobs y la autenticación manual remota, todavía no está validado en Linux/ARM. El ZIP Windows no es un instalable Linux.

| Componente | Evaluación concreta |
|---|---|
| Node.js | El paquete probado usa Node 24.13.0. La rama 24 dispone de binarios Linux x64 y ARM64; utilizar una revisión mantenida de esa rama, no copiar node.exe. El código usa `util.parseEnv`, por lo que un Node antiguo sin esa API no sirve. [Descargas oficiales de Node 24](https://nodejs.org/en/download/archive/v24.22.0). |
| Playwright / Chromium | Proyecto fijado en Playwright 1.62.1. Instalar dependencias con el lockfile y descargar los navegadores para Linux y su arquitectura. No trasladar la carpeta Windows `browsers` ni asumir portabilidad de `node_modules`. La documentación actual contempla Ubuntu 24.04 y ARM64, pero debe comprobarse la versión fijada antes de desplegar. [Sistemas soportados](https://playwright.dev/docs/intro), [instalación de navegadores y dependencias](https://playwright.dev/docs/browsers). |
| Distribución | Preferir una imagen Ubuntu compatible y marcada Always Free Eligible en la consola. No dar por soportada Oracle Linux solo por ser la imagen predeterminada del proveedor. Es una recomendación técnica, no una prueba ejecutada. |
| Windows | `Abrir.cmd`, `Conectar LinkedIn.cmd`, `Buscar.cmd`, node.exe y el asistente que abre `cmd.exe` son envoltorios Windows. En Linux se usarían los entrypoints existentes `node src/start.js`, `node src/connect-linkedin.js` y, solo tras autorización, `node src/hunt.js`; no hace falta rediseñar el Analyzer. |
| InfoJobs | `src/infojobs/browser.js` exige `channel: 'chrome'`, tiene User-Agent Windows y parámetros específicos. Chromium instalado no garantiza disponer de ese canal comercial en ARM. Es una dependencia pendiente de verificar/adaptar antes de declarar portable la funcionalidad completa. No se alteró ni probó ahora. |
| Persistencia | Separar directorios, `.env`, puertos, datos, perfiles y browser-profile por candidato. El historial actual de Mariano ocupa 11,84 MiB y usa JSON. Guardar en volumen persistente; preservar los tres JSON profesionales, historial, configuraciones y fuentes de las citas. Respaldar fuera de la VM antes de mover o actualizar. Las claves locales requieren permisos adecuados en Linux. |
| Programación | El proceso existente `src/start.js` mantiene UI y temporizador; funciona solo mientras vive. En una migración futura podría mantenerse con systemd, conservando programación propia por instancia y evitando duplicarla con cron/timers. Actualmente todo sigue en cero; no se creó ni habilitó ningún servicio. |
| Acceso | La UI escucha en 127.0.0.1 y no tiene autenticación multiusuario. Mantenerla privada y acceder mediante túnel SSH; no abrir directamente sus puertos a Internet. Es una conclusión de la revisión del código actual. |

**Recursos y continuidad:** la documentación vigente indica A1 ARM con un equivalente total de **2 OCPU y 12 GB**, hasta **200 GB** combinados de volúmenes y **cinco backups** incluidos. También advierte falta de capacidad e instancias inactivas reclamables tras una ventana de siete días con sus criterios de utilización. Verificar la cuota real de la cuenta/región al migrar; no presuponer los antiguos 4 OCPU/24 GB ni capacidad libre garantizada. [Always Free oficial](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

Como estimación, una A1 con esos recursos debería permitir dos aplicaciones ligeras y navegadores ejecutados de forma escalonada; no es un benchmark. Las micro AMD de 1 GB no son una base aconsejable para dos navegadores y una sesión gráfica. La baja carga de este proyecto hace relevante el riesgo de reclamación: conservar copias recuperables, sin generar carga artificial para evitarla.

**LinkedIn es el principal riesgo operativo:** `connect-linkedin.js` abre un navegador visible. Un servidor Linux sin escritorio necesita un entorno gráfico accesible de forma privada para que la persona haga login y verificaciones. Xvfb permite ejecución gráfica, pero por sí solo no entrega una pantalla interactiva al usuario. [Playwright sobre Linux con pantalla virtual](https://playwright.dev/docs/ci).

Crear una sesión nueva en Oracle, por candidato. No asumir que las cookies/sesiones Windows funcionarán en Linux, ni copiarlas desde el Hunter original. Persistir después el browser-profile de Linux y nunca abrirlo simultáneamente desde dos procesos. La [documentación de contexto persistente](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context) describe su almacenamiento y exclusividad. Un cambio de equipo o IP puede requerir otra autenticación o ser rechazado por LinkedIn; no hay garantía de aceptación ni se propone eludir controles.

Antes de migrar: comprobar arquitectura/distribución, navegador y canal de InfoJobs; ejecutar smoke offline; tomar respaldo íntegro; iniciar sesión manualmente en el entorno destino; y solicitar autorización separada para búsquedas y programación. El coste de OpenAI sigue siendo independiente de la gratuidad de Oracle. No se desplegó nada.
