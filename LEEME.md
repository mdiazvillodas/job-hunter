# Job Hunter 0.2 simple — candidato local a validación

En el paquete Windows, abrí **Instalar.cmd**. Elegí un nombre corto, puesto, ciudad y un puerto diferente por candidato. El instalador crea una carpeta en `instances`. Abrí **Abrir.cmd** dentro de ella para ver resultados, importar o editar el perfil y configurar la clave OpenAI. **Buscar.cmd** ejecuta una búsqueda manual: no se ejecuta durante la instalación. El límite inicial es cero análisis pagos. Antes de buscar en LinkedIn, abrí **Conectar LinkedIn.cmd** dentro de tu instancia. Iniciá sesión manualmente y cerrá el navegador cuando termines; permanece abierto durante la autenticación y conserva la sesión en su propio `browser-profile`. Mientras está abierto se impiden búsquedas simultáneas de esa instancia. No se copian sesiones del Hunter original. Cada candidato inicia sesión en su propio navegador; necesitás Chrome instalado para InfoJobs y acceso a LinkedIn.

El paquete incluye Node y dependencias. No necesita instalar npm. Conservá la carpeta completa para conservar historial, perfil, configuración y cookies. No la compartas: puede contener datos privados y credenciales. La clave se guarda localmente en `.env`, sin cifrado adicional. Elegí una carpeta privada de Windows.

La guía Markdown se descarga desde Perfil. Si falta información, el Hunter lo indica y permite continuar. Los encabezados permiten localizar información, pero no bastan para aprobar el perfil. El diagnóstico busca tareas concretas y herramientas o métodos contextualizados, e indica preguntas por responder. Es orientativo: no verifica la verdad de las afirmaciones ni bloquea búsquedas. Ver docs/diagnostico-corregido.md.

Las instancias no comparten datos ni sesiones. Solo comparten los archivos de dependencias de su instalación. El perfil original de Mariano se conserva como JSON y se muestra sin edición, para evitar perder su calibración. Las instancias nuevas usan un Markdown editable y búsquedas propias. InfoJobs conserva la configuración original en Mariano; las nuevas instancias usan LinkedIn para evitar heredar su provincia.

La configuración permite programar búsquedas cada 15 minutos o más. Inicialmente está desactivado. Al activarlo autorizás las búsquedas y el consumo según el límite configurado. Funciona mientras Abrir.cmd está abierto; al reiniciar se conserva la configuración y espera el intervalo completo antes de buscar. No crea tareas de Windows. El trigger original sigue disponible para automatización externa, con token. El piloto previo y sus defectos están documentados en docs/validation-pilot. Las correcciones posteriores se validaron localmente; no se repitieron llamadas a OpenAI ni scraping real. La autenticación real y el comportamiento del modelo con las instrucciones corregidas siguen pendientes de validación autorizada. El instalador es una carpeta portable con asistente local, no un MSI firmado.

La explicación distingue texto del perfil, inferencias de transferencia y experiencia no documentada. La fuente se recupera como unidad completa, no como una cita redactada por IA. No certifica competencias ni cambia los puntajes. Los análisis históricos sin referencias se indican como tales; las explicaciones originales se conservan en el historial para auditoría. Ver docs/presentacion-extractiva.md.

LinkedIn selecciona automáticamente el flujo clásico o conversacional según la pantalla disponible. No hay que elegir Premium ni cambiar de versión al vencer la suscripción. En la interfaz conversacional la ubicación se comunica como orientativa; la jornada se comprueba en la ficha antes del análisis. Jornadas incompatibles se omiten y desconocidas quedan pendientes. Si la pantalla anuncia ofertas y no se reconocen tarjetas, se informa un error. Este paquete aún requiere validar una ejecución real acotada; las pruebas incluidas son locales. Ver docs/linkedin-dual-simple.md.

La revisión rc.2 añade **Buscar ofertas** en la interfaz: solo un clic inicia el runner existente, respetando el bloqueo y la configuración de tu instancia. No se inicia ninguna búsqueda al abrir la página. Para Oracle, la capa común de acceso y sus requisitos HTTPS están documentados en scripts/oracle/README.md; no afecta al uso local por candidato.
